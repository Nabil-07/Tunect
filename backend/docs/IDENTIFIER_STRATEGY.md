# Identifier Strategy (Backend)

Canonical identifier format for domain entities is **CUID**.

## Rules

1. Prisma primary keys are CUID and remain the source of truth.
2. API DTO identifiers for domain entities must validate as CUID.
3. UUID must not be introduced for domain IDs in controllers, services, or DTOs.
4. S3 object keys generated by backend code must use CUID-based filenames.

## Upload Key Prefixes

Use only these top-level prefixes for new uploads:

- `avatars/`
- `kyc/`
- `certificates/`
- `study-materials/`
- `test/`

Any non-canonical folder should be normalized under `test/`.

## Legacy Compatibility

Some DTO validators may temporarily accept UUID values for backward compatibility with older clients.
This is transitional behavior only; new integrations must send CUID values.
